# Protected page content and browser-attempt alerts

Authenticated software pages block ordinary mouse text selection, Select All, Copy and Cut outside editable fields. Entry/search controls, Excel/IMEI bulk paste, scanning, dropdowns, authorized printing and downloads remain available. No operating-system clipboard is read or cleared. Sign-in and signed-out pages are not restricted.

Browser-delivered PrintScreen, Alt+PrintScreen, Windows snipping, Edge capture and macOS capture shortcuts are cancelled where possible and trigger a brief opaque screen cover. A website cannot reliably stop or detect operating-system captures, a camera, another app, browser tools that deliver no event, or captures of downloaded files. This is a UI deterrent, not data-loss prevention. Do not claim that a screenshot succeeded or was prevented.

Observable selection/copy/capture attempts append high-priority red rows in Suspicious Activity, showing the authenticated account, page, server recording time, action and explanation. Capture rows explicitly say completion is unknown. Events are client-reported review signals, can be suppressed or fabricated by a modified client, and are never automatic proof of misconduct or grounds for an automated penalty. Blur, tab switching, right-clicking and ordinary controls are not treated as screenshots.

The server supplies the actor and timestamp, requires active page access and the office boundary, and rejects unauthenticated, inactive or unauthorized callers. View-only accounts can submit only their own bounded telemetry; this grants no business editing or alert-reading access. No selected text, clipboard contents, images, passwords or tokens are sent. Request IDs make retries idempotent. A two-second per-action browser debounce and 30 new alerts per account per minute limit noise. At most 20 unsent events stay in page memory; closing/signing out discards them. An offline attempt is not guaranteed to be recorded.

Existing Suspicious Activity view/review/download permissions apply. Its new Protected text / screen-capture attempts rule can be disabled through the existing audited rules UI; the UI selection restriction remains. Normal alert pages contain 50 records; complete CSV downloads retain the existing separate limit. Same-browser notifications refresh immediately after accepted events; authorized open pages also poll every 15 seconds.

Run Publish-GreenLoop-Content-Protection.ps1. The publisher checks previous installations and asks for the additive content-protection SQL only when missing. Run its entire clipboard SQL in a NEW Supabase query, confirm installed_content_protection_version = 20261109-content-protection-1, then press Enter in PowerShell. No Edge Function, JWT, secret or new permission checkbox is required. Installation adds private security metadata and logging only; it does not rewrite stock, IMEIs, quantities, assignments or history. No website publication or live SQL installation was performed while preparing this package.
