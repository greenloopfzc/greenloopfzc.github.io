# Greenloop transfer report summary

Greenloop Section > Reports > Transferred Stock Data shows three summary cells: Transferred to Chaman, Received by Chaman, Balance Pending. Example:50 dispatched and40 Chaman receipts gives50 /40 /10. Historical Chaman receiving remains40 even if some phones are later returned to Greenloop. Physical shop balance and return-to-Greenloop counters are separate report concepts.

Migration298 extends the existing protected read response with transfer_summary. List totals sum all matching delivery quantities after search/date filtering and before50-record pagination. A delivery search finds matching delivery cards and counts those cards' complete quantities. Within delivery details, filters count the matching phone rows before paging. Empty selections yield zero. Received is based on that outbound delivery's recorded Chaman receipt, so return dispatch/company receipt does not reduce it. Existing transfer, receipt, return, correction and stock records are read only.

The UI renders exactly the three cells in three desktop columns, stacking on small screens. Missing or inconsistent scoped totals cause an explicit report error and clear the summary. Other report types keep their existing counters. Complete PDF/Excel report payloads include the same scoped summary, and delivery-list column labels match it. The private read permission/office checks remain in place; the atomic installer updates only matching function integrity receipts and verifies its new version marker.
