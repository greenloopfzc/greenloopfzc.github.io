# Original-stock selector correction

Business stock selectors show one entry per original receipt ID. A private replacement intake must never be shown as an original-stock label with a different hidden ID. Original batch, invoice, quantity and received date are taken together from the canonical original receipt. Different genuine deliveries remain separate even when both contain 342 units or belong to the same supplier.

The shared stock catalogue now exposes original receipts for Initial QC, Lab & Glass Issuance and other stock consumers while retaining private child identity resolution internally. Accounts IMEI DATA, Stock Return context, stock analysis/replacement report catalogues and stock filter facets use canonical IDs and metadata. Read-only filters referencing a known stale child ID resolve to the original stock. Native server queries supply the original phones and linked replacements, keeping paging and complete exports unchanged.

This correction does not remove a receipt, merge phones, rewrite an IMEI, change a stock quantity or submit a return/save/transfer. Actual replacement dates and exact old/new IMEI pairings stay in replacement history. Private reserved IMEI Entry intake IDs and write arguments stay intact. Supplier/customer name permissions remain enforced; supplier/batch original quantity labels remain visible to allowed viewers.

Run `outputs/Publish-GreenLoop-Stock-Selector-Fix.ps1`. This is a frontend correction with no additional SQL, Edge Function, JWT setting, secret or permission tick. Earlier required updates, including the Original Stock Replacement repair and IMEI replacement history, are checked and installed only if missing. After LIVE - VERIFIED, press Ctrl+F5 and select the original batch again.

Validation uses an isolated PostgreSQL fixture reproducing the reported failure: the child ID returns an empty Accounts/QC list while the original ID returns the linked replacement. Actual Chromium runs the shared config RPC layer and native Accounts, QC inspection/issuance and Stock Return controllers. It verifies one original option, real data loading, distinct equal-size deliveries, original dates and IDs, report facets, unchanged manual writes/intake reservations, preserved red/green return/replacement rows, name privacy and Office clearing. No live database writes or publishing are performed by these tests.
