# Installation verification without repeated dependency chains

The existing public version routines remain unchanged. The new read-only verifier evaluates the same reviewed SQL bodies and their metadata, hash tables, row security, grants, triggers and office registrations. Dependencies are checked once in topological order per request; only verified dependency results replace their repeated function calls. Reviewed procedural checks retain their original implementation.

A fixed catalog records 122 reviewed marker source hashes, language, volatility, security mode, settings and dependencies. The Bulk IMEI Correction marker matches the canonical 11-object installation and its private-function permission checks. Unknown or changed definitions, grants, failed dependencies, business-helper hash mismatches and engine tampering remain failures. The component endpoint returns version status only, not stock, account or customer data. Private catalog, evaluator and integrity records remain inaccessible to anon/authenticated users.

The publisher first verifies this engine's independent marker and offers its additive SQL if absent. All existing checker helpers then require their original exact versions through the component verifier. There is no direct-success fallback for timeouts. Diagnostic Battery BH, IMEI badge, previous business records and page permissions are preserved.

Run the updated Publish-GreenLoop-Diagnostic-Battery-BH.ps1. The first requested SQL installs only the read-only verification engine. Further missing authorized updates, including the Diagnostic Battery issued rule, are installed and verified in their existing order. Nothing publishes until every required check passes.
