# Damaged part requests in Lab & Glass and Parts

Lab & Glass has a small Damaged checkbox immediately after a selected part quantity, with an optional reason. The existing Order Additional Parts / Send to Parts action saves the mark and exact new request atomically. A marked request appears checked in Parts, and Parts can mark an unmarked pending request using Save mark. Discard restores the saved mark. A saved request shows the operator, UAE date/time, originating department and optional reason. The checked label/badge uses light red. Existing saved Lab parts show the same damage badge after refresh.

The mark belongs to a specific immutable part request and order/phone, not its part name. A later request for the same named part starts unmarked unless deliberately checked. Existing requests default to unmarked; no historical marks are invented. The flag is independent of requested/issued/returned/installed quantities, inventory balance, return classification and supplier stock. No quantities, stock costs or parts inventory damage transactions are automatically changed by this annotation.

SQL322 is additive: existing protected Lab submission/additional-order APIs and Parts order reader remain unchanged. New wrappers preserve their office/page/employee/role/workflow/stock checks. The small Parts write requires Issue permission, a current active Lab/Glass visit, exact order/request membership and the reviewed order revision. Completed, cancelled, fully issued or earlier-visit requests cannot be relabelled. View-only users see the saved state without edit controls. Private state and command tables use RLS and deny anonymous/authenticated direct access. Write commands have actor-bound idempotency tokens; retries do not duplicate requests, audit events or stock operations. Damage changes advance the order revision so a stale issue/mark cannot silently overwrite another operation.

Each change appends before/after flag and reason, exact request ID, part, actor and source to Parts activity history and the phone journey. Lab order plus all marks roll back together if any step fails. Existing quantities, issues, installations, returns, assignments, services, timers and battery handling retain their existing behavior. First parts submission and additional parts both work. Existing Final QC-return provenance is retained through the same reviewed read-only provenance rule. The old Lab/Parts/report routines and integrity receipts are not rewritten.

Parts keeps prepared Issue Qty, optional price and source when saving a damage mark. Failed saves keep the draft and action token. Unsaved marks pause Issue and automatic detail refresh until Save mark or Discard. Closing the detail explicitly discards an unsaved mark. Office/sign-out/access changes clear private detail state and stale replies cannot reopen it. Lab drafts retain the checkbox/reason through save failures, then clear after success as before.

Parts Usage Report includes Damaged requests and per-phone damage operator, date, source and reason, including complete PDF/Excel exports. This counts distinct marked requests rather than units: two partial issues from one request still count one damaged request. It reports requests that contributed actual recorded issues; pending requests remain visible in Lab/Parts and their activity history. Filters, original receipt labels, independent report/search/download/name permissions,50-row pages and snapshot-checked complete exports remain enforced. Damage metadata is part of the snapshot. Supplier and batch original quantities, stock counts and financial confidentiality remain preserved. The PDF renderer accepts optional report-specific column weights/word wrapping; old report layouts keep their defaults.
