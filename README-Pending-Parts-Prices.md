# Pending Parts Prices

Release / marker: 20261030-pending-parts-prices-1
SQL result: installed_pending_parts_prices_version

Parts has a fourth card, Pending Parts Prices, with a distinct-phone pending badge. Issued parts with a missing private unit price are grouped by supplier, original receipt/batch and invoice, model, GB, color, part, Local/China source and currency. Different stocks, sources and currencies stay separate. iPhone model-prefix aliases combine, while different models and storage sizes remain distinct. Unlinked legacy jobs stay separate rather than being assigned to an invented common stock.

For 50 matching phones, each issued one Housing, the report shows one 50-phone / 50-part line. Saving AED 10 per part records all 50 missing issue prices for AED 500 and removes those issues from the pending report. Recorded zero prices are complete, not missing. Issued quantities include returned/damaged units because their historical issue price still matters; returned quantities are explicit in filters, details and affected quantity cells. Phones with several pending parts count once in the badge and filtered phone total. Completed / Final QC / Ready Stock / exported phones remain eligible for missing-price completion without moving them or changing their workflow.

The compact table shows supplier code, invoice/batch, phone details, part/source, phones, issued quantity, unit price and value. Filters contain supplier, invoice, batch, model, GB, color, part, Local/China/Not recorded source, phone count, issued quantity, returned quantity, UAE issue date and currency. Date filters select actual issue units before grouping: saving one day prices only that day's reviewed issues. Heading sorting is flat and filters update the totals. Clicking a phone count opens the exact issue/IMEI list.

No historical source is guessed. Existing issues without explicit Local/China provenance appear as Not recorded. A source can be chosen for a whole unknown-price group when saving its price, or selected issue lines can be assigned a source in the phone-details window to split a mixed group first. Source-only assignment leaves prices pending. Both ordinary Parts issue and Technician Parts Report Bulk Issue have optional Local/China fields. Bulk review can apply one source to all selected issue lines, with individual overrides. The original issuers and all their stock, quantity, return and revision checks remain in use through compatible source-capture wrappers.

Existing Parts View reads this report and its phone details. Search and Sort keep their existing separate grants. The existing Issue parts action writes prices and sources; no new permission checkbox is introduced. View-only, non-Parts, TV-only, anonymous and unverified Office Only sessions cannot write. New unit prices and source history remain in protected private tables and are not copied into public stock ledgers or device events. Public inventory costs and earlier prices stay unchanged.

Each save locks and rechecks the reviewed group. Changed membership, metadata or earlier prices invalidate its token. Every selected issue price/source is saved in one transaction, with immutable private audit and an exact retry key. A late failure rolls back every change. A lost/uncertain response keeps the same request fixed for Retry last save, preventing duplicate saves. Source-only changes are also audited and retry-safe. Pricing/source audit remains permanent under the existing deletion policy; operational supplier/batch deletion remains compatible.

Migration 226 adds private provenance/audit storage, read/pricing/source APIs, compatible issue wrappers and an integrity marker. Installation enters no prices, assigns no sources, issues no parts and changes no existing permission catalog or workflow function. Previous database versions are preserved. No Edge Function or JWT changes are required. The cumulative publisher stops on changed database definitions, connection errors or newer unreviewed Git history, and verifies published assets against the tested source.

Validation uses disposable PostgreSQL and browser fixtures: the 50-phone example, Local/China splitting, private pricing, zero prices, date subsets, stale groups, late rollback, idempotent retries, completed phones, atomic source capture during bulk issue, deletion compatibility, permissions and responsive layouts. No live phone, stock or price records were changed during testing.
