# Stock Parts Cost

Version: 20261030-stock-parts-cost-1
Final SQL result: installed_stock_parts_cost_version

Reports has a separate Stock Parts Cost card. Its own collapsed Filters panel selects supplier code, original invoice, Stock/Batch and optional UAE receipt dates. Search matches supplier code, invoice or batch. Header sorting uses the existing Reports Sort grant. This report includes each selected receipt's complete recorded parts history, irrespective of its current department, Ready Stock or export status; the other Reports date range does not silently restrict it.

Stock rows show distinct entered phones, recorded net parts cost and unpriced net quantity. Click a stock to see one row per physical phone, with IMEI1, device number, model, GB, color, workflow status, recorded cost and pending-price status. Click a phone for every issued/manual part across its jobs in that stock, including Local/China/Not recorded source, quantity, approved restock, damage/faulty disposition, unit price, net recorded value and UAE timestamp. Receipts with no entered phones remain visible. Repeated receipts from the same supplier remain separate; invoice selection can include more than one distinct batch. Unlinked legacy jobs stay separate.

Cost is issued value minus approved Not Needed/restocked value. Damaged and faulty parts stay charged; a replacement issue adds its own cost. Installation records linked to an issue are not charged a second time. Rejected or pending return reviews do not become a restock credit. Recorded zero prices are valid; missing private prices and unpriced manual parts remain pending rather than being guessed as zero. Fully restocked units have zero net cost even if their historical price remains unrecorded. Legacy public issue prices are used only when there is no private authoritative price and no unpriced Parts Flow marker. Different currencies remain separate throughout stocks, phones, details and totals. Supplier names are never returned by the new API.

Confidential access is a new read-only tick under User Access > Reports: View Stock Parts Cost (confidential). Existing effective permission defaults are frozen before the tick is added, so ordinary Reports/Parts accounts do not acquire confidential cost access automatically. Owners/Super Admins with Reports View get the tick initially. An authorised manager of user access can grant it to others, including view-only accounts; Reports View is also required. Reports Search and Sort retain their independent controls. No write access is needed to browse stock/phone/part details.

Migration 227 adds only a read API, private helpers, integrity records and the permission definition. It does not enter, issue, price, install, return, move or delete any business record, and it does not rewrite the old Device Cost report. Source data uses the existing private issue prices, including prices completed in Pending Parts Prices. Its read API has an Office Only wrapper, active-staff and TV-only checks, and no anonymous data access. Private helpers stay inaccessible to clients. Installation replay preserves configured permissions. No Edge Function deployment or JWT change is required.

Validation uses disposable PostgreSQL snapshots and browser fixtures, including exact stock/phone/part responses generated by the database test. It covers private/zero/missing prices, same supplier repeated batches, returns/replacement, completion without double counting, currency separation, legacy manual entries, 50-phone aggregate totals, date scope, permissions, stale stock/device rejection, unavailable reads, view-only navigation, late responses, dark/mobile layout and the actual User Access checkbox. No live records were used or changed in testing.
