# Technician Workbench: all pending phones

Click Total Pending in Technician Workbench to view every technician's saved pending Lab / Glass phone details in one window, including unassigned phones. Each phone occupies one table row showing technician, IMEI, department, model, GB, color, Initial BH, supplier code, invoice, batch, required parts and issue status, services, workflow status and elapsed time. Technician and status filters and IMEI scanning/text search use the existing Lab search permission. Each new scan replaces the previous one, and Show all restores the list.

Complete → Final QC sends that single phone through the existing Bulk Lab Transfer readiness and idempotent transfer APIs. It requires the existing Lab entry permission and rechecks the phone's latest readiness and assignment on the server. Pending parts, returns, unsaved services and unassigned phones cannot be bypassed. Unsaved workbench drafts prevent completion. Failed or uncertain replies retain the original transfer request for confirmation, so retrying does not issue a second handover. On success the phone is removed from the overview and the workbench refreshes.

This release includes the preceding Final QC Layout correction. No new SQL, permission or Edge Function is needed for this feature; the existing Bulk Lab Transfer APIs are required. The publisher verifies the previous installed database and Edge versions, refuses to overwrite newer GitHub history, and verifies the published website files after a normal push. It uses the existing permission-checked employee board and ranked workbench readers; supplier names are deliberately not included. Each overview load runs at most three concurrent reads, only after the overview is opened. Failed reads display an error without presenting incomplete totals.

Run `outputs/Publish-GreenLoop-Lab-Pending-Workbench.ps1` using PowerShell. `-CheckOnly` validates the local tested source without network requests. The normal command checks the prior installations and publishes the prepared commit, then verifies the live website. If an earlier prerequisite is missing it retains the preceding publisher's installation flow. No new installation is added by this feature.

After a successful publish, refresh Technician Workbench with Ctrl+F5, click Total Pending, scan a phone, and use its Complete → Final QC button when ready. All existing Lab entry/search permissions still apply.

The overview is a saved-data snapshot, refreshed on opening or with Refresh. Phone totals count unique devices. If a phone has multiple pending Lab/Glass work steps, its saved details are combined into one row. Pending time uses the existing server-provided Lab clock, including earlier Lab arrival times supplied by the installed return-clock update. This patch does not alter that clock.

Validation: 18 isolated browser cases passed, covering cross-technician data, filters, keyboard opening, zero results, read failure, permissions, repeated work steps, HTML escaping, stale replies, mobile/dark layout, B-DEPT isolation, successive scans, completion, blocked readiness, unsaved drafts, changed assignments and idempotent retry. Two additional browser checks passed with the complete workbench scripts and permission layer loaded, for edit and view/search access. These are local mocked-API checks; no production phone was transferred during validation.
