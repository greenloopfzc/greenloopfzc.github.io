# Reuse the rejected scanner row

Initial QC, Lab & Glass Issuance and Final QC used to focus the next row as soon as the fifteenth digit arrived, before the server had accepted the phone. They now advance only after a successful current load and only while the user still owns that scanner focus. A rejected/duplicate manual scan clears its own field and returns to that exact field after OK/Escape. Repeated rejections reuse it; they neither add nor leave an unused line. Loaded phones and manual edits are preserved. Enter/Tab during the pending check cannot advance the row, and a fast scanner's terminator cannot activate an immediately opened duplicate dialog.

IMEI Entry has the same behavior in its 50-line batch table and single form. Its exact manual input is carried through the protected duplicate check; rejection clears only that IMEI and retains the rest of the prepared specifications. A duplicate in the same tray is caught locally as well. A valid response advances the batch scanner; stale checks cannot clear newer values or a different receipt. Checking a scan never receives a new stock phone. Save/Auto Save retain their existing authoritative duplicate and stock validation, and pending checks block premature saving. Bulk paste and cable-created drafts keep their existing separate review/save behavior.

Browser validation uses the actual pages, scanner, shared access guards and isolated fixture responses: repeated known/unknown/secondary/local duplicate scans; OK/Escape recovery; delayed reads; Enter/Tab terminators; consecutive accepted scans without blank gaps; saved/loaded rows and specification retention; manual/automatic Save; no unintended writes; stale/office/sign-out/read-only guards; 105-row QC paste and 50-line IMEI entry. The prior scanner/battery/loading regression suite passed26 groups. No live business records were changed.

This is a frontend update with no new SQL migration. Publish-GreenLoop-Same-Row-Scanner-Fix.ps1 retains all existing prerequisite/version checks and the repaired atomic Battery Cell/performance installers. It only requests prerequisite SQL if that prerequisite is not already verified. After publishing, Ctrl+F5 on Initial QC, Issuance, Final QC and IMEI Entry loads the new scripts. Codex has not run live SQL or pushed this change.
