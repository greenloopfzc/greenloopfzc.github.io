# IMEI activity date/time and chronology

IMEI Search now displays the saved activity date and time to seconds in Asia/Dubai, including compact visits, Full activity, Reports Corrections, selected-phone history popups and replacement receipt dates. The existing Stock Journey detail consumer shares the same formatter and chronological ordering. Initial BH, Final BH, Supplier Grade, GL Grade and Final Grade remain separate.

Full activity and compact visits use one ascending saved timestamp order, retaining sub-millisecond precision for sorting. Equal-time records retain the source order except for explicit saved From/To or destination evidence. There is no universal cross-table audit sequence in this response: unresolved equal-time records are marked Same time, not presented as a separately timed sequence. A generic department rank no longer puts Issuance after Ready Stock. Repeated visits have Visit labels; supplemental work is kept with its preceding visit, with a limited missing-arrival fallback that cannot cross a saved QC failure. Chaman dispatch, receiving, return dispatch and Greenloop return receiving remain distinct milestones.

Assignment, repair-work snapshots and timer actors are labelled as technicians; actual movement/correction operators remain By. Missing dates, time or actors are not invented. A date-only value shows Time: Not recorded. Automatic direct Initial QC to B-DEPT system records remain preserved and distinguished from a real Final QC inspection.

This is a display-only change. No new SQL migration, extra polling or new history RPC is introduced. Existing permissions, supplier-name masking, read cancellation, correction snapshots/50-row paging, manual workflow writes and all immutable audit records are retained. It does not backfill missing historical timestamps or certify a live phone's original records.

Local validation: real Chrome main page and bulk history popup at desktop/mobile sizes in light/dark modes with a non-UAE laptop timezone; UAE rollover, seconds, missing times, independent jobs, sub-millisecond order, explicit B-DEPT/Issuance routes, rework visits, direct-route records, complete record retention, correction paging, name masking and stale Office replies. Existing journey rework and detail-page regressions are also checked. The standalone fixture harness is tools/test-imei-activity-time.cjs (requires the installed Playwright/Chrome paths used by this workspace). No production data is used by that harness.

Publish using the tested PowerShell package supplied in the gl4 outputs folder. The publisher retains all earlier database prerequisite checks and only requests older SQL if that prerequisite is absent. Codex has not run live SQL or pushed this update. After publishing, Ctrl+F5 on IMEI Search.
